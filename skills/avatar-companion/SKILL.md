# アバターの使い方（MUSE向け作法）

アバターはあなたの「声と体」です。判断はすべてあなた（MUSE）側で行い、
アバター側に決め打ちの受け答えは持たせません。

## つなぎ方（ユーザーが番号を伝えてきたら）

ユーザーが「アバターとつないで。番号は 123456」のように6桁の番号を
伝えてきたら、接続の合図です。次を実行してください：

```
python3 pair_claim.py <6桁の番号>
```

- 番号そのものが合言葉です。ファイルや JSON をユーザーに作らせないこと。
- 接続情報は `~/.avatar2/config.json` に保存されます（権限600）。
  脳キーを画面に出したり、ユーザーに読み上げたりしないこと。
- 番号の有効期限は10分です。期限切れ（410）や番号違い（404）のときは、
  理由をそのまま伝え、アプリで新しい番号を出してもらうよう案内すること。
- claim の次に、脳デーモンが起動しているか `avatar_status` で確認する。
  起動していなければ、同梱のデーモンを常駐させる：
  `python3 brain.py run`（常駐プロセスとして起動する）。
  デーモンが中継に接続すると、アプリ側に「つながりました」と出る。

## いつアバターで話すか

- 朝の報告、会議のプレゼン、秘書の予定報告など、「声で届ける」場面で使う。
- 進行中のプロジェクトがあるときは、まず「（プロジェクト名）の進捗を
  お伝えしましょうか」と提案し、本人が「教えて」と言ってから報告する。
  頼まれていない長報告はしない。

## 会話の回し方（速さが核）

1. `avatar_listen` で次の発話を待つ（発話はデーモンが保持し、待ちは
   即座に起きる。ポーリングの間隔待ちはない）
2. 内容は自分の道具・連携で調べ、文脈で判断する
3. `avatar_say` で返す。**最初の一文を先に送り、続きは同じ
   `utterance_id` で送る**（デーモンが文単位で合成して先行送信するので、
   初声が速くなる。全文を書き上げてから一括で送らない）
4. 声は発話のキャラの固定ボイスで自動決定される。話者を自分で
   選ばないこと（選ぶとキャラと声が食い違う）
5. 連携していない機能を頼まれたら、黙って失敗せず、会話の中で
   「MUSE側で（連携名）と接続すればできます」と案内する

## 道具の使い分け

- 発話への回答: `avatar_say`（`utterance_id` 付き）
- 発話に紐づかない発声（朝の報告など）: `avatar_say`（id 無し）か
  `avatar_report`（文の列を順に）
- 状態確認: まず `avatar_status`。デーモン未起動なら起動を、
  ステージ未接続なら、その旨を正直に伝える
- 背景はアプリ側で選ぶもの。脳側の道具にはない

## 注意

- ユーザーは仕組みを意識しません。内部の道具名やエラー文をそのまま
  読み上げないこと。
- 分からないことは分からないと短く言う。捏造しない。
